# Спецификация проекта (командная)

Общая схема данных: [Схема базы данных](Database-Schema.html).

---

## 1. Диаграмма вариантов использования

<img width="773" height="1537" alt="Use_case" src="https://github.com/user-attachments/assets/6a7a810e-2859-4d52-81e1-b3f19909ac31" />

**Описание.** Кто из акторов (командир авиаотряда, член экипажа) инициирует какие сценарии. Варианты с пометкой `(*)` доступны экипажу в ограниченном виде (данные только своего вертолёта / своих рейсов / своих начислений). Кратко перечислите главные варианты и заметки на диаграмме (если есть).

---

## 2. Диаграмма структуры модулей (аналог диаграммы классов для C++)

[![classes](https://github.com/user-attachments/assets/6fad75b7-bd89-40fc-97aa-7b695e323129)](https://github.com/user-attachments/assets/6fad75b7-bd89-40fc-97aa-7b695e323129)

**Описание.** Приложение модульное: заголовки в `includes/`, реализации в `src/`. Укажите, как связаны `common`, `db`, `auth`, `queries`, `mutations`, `payroll`, `storage`, `main`, и что все обращения к данным идут через SQLite C API.

---

## 3. Диаграмма деятельности — вход в систему и работа с меню

<img width="659" height="1088" alt="activity" src="https://github.com/user-attachments/assets/1ef015a4-1440-4eb9-ae8a-e12c83834f38" />

**Описание.** От запуска `helicopter_app` до выхода: открытие БД, опциональная загрузка демо-данных (`HELI_SEED`), `auth_login`, формирование сессии (командир / экипаж), цикл меню, проверка прав для пунктов командира и фильтрация по вертолёту для сценариев с `*`, закрытие БД.

---

## 4. Диаграмма деятельности — добавление рейса (проверка ресурса)

<img width="486" height="535" alt="activity_2" src="https://github.com/user-attachments/assets/1a12d6bb-2a84-437b-b8ac-40c03614a035" />

**Описание.** Ввод данных рейса, отказ в приложении, если экипаж пытается внести рейс по чужому вертолёту, затем `INSERT` и срабатывание триггера `trg_air_flights_resource_check` в SQLite (откат при превышении летного ресурса после капремонта).

---

## 5. Диаграмма последовательности — отчёт «налёт и ресурс»

<img width="762" height="377" alt="sequence" src="https://github.com/user-attachments/assets/565cea5b-dc02-43bb-b877-fdd49e905bc0" />

**Описание.** Пользователь выбирает пункт меню → `main` / `run_menu` вызывает функцию из `queries.cpp` → запрос к БД → текст отчёта в консоль. Для экипажа в запросе учитывается фильтр по вертолёту из сессии.

---

## 6. Диаграмма последовательности — расчёт начислений за период

<img width="815" height="459" alt="sequence_2" src="https://github.com/user-attachments/assets/62039cb2-8e93-4066-a5a6-c7304dd020f0" />

**Описание.** Командир задаёт даты → вызов `payroll_compute_squad_period` → транзакция в SQLite: очистка старых строк периода при необходимости, вставка в `AIR_PAYROLL_PERIOD`, фиксация → отображение таблицы начислений.
