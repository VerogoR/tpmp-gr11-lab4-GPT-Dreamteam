Спецификация проекта (командная)

Общая схема данных: Схема базы данных.

1. Диаграмма вариантов использования

Кто из акторов (командир авиаотряда, член экипажа) инициирует какие сценарии. Варианты с пометкой (*) доступны экипажу в ограниченном виде.

2. Диаграмма структуры модулей

Приложение модульное: заголовки в includes/, реализации в src/. Модули common, db, auth, queries, mutations, payroll, storage, main работают через SQLite C API.

3. Диаграмма деятельности — вход и меню

От запуска helicopter_app до выхода: открытие БД, опциональный seed, auth_login, формирование сессии и цикл меню по правам роли.

4. Диаграмма деятельности — добавление рейса

Ввод данных рейса, проверка прав экипажа по вертолету, INSERT и работа триггера trg_air_flights_resource_check (откат при превышении ресурса).

5. Диаграмма последовательности — отчет «налет и ресурс»

Пользователь выбирает пункт меню, затем main/run_menu вызывает запрос из queries.cpp, после чего отчет выводится в консоль.

6. Диаграмма последовательности — начисления за период

Командир задает даты, вызывается payroll_compute_squad_period, затем транзакция записывает результат в AIR_PAYROLL_PERIOD.

7. Диаграмма компонентов

Исполняемый модуль, зависимость от libsqlite3, SQL-скрипты и файл БД.

8. Диаграмма развертывания

Рабочая станция с бинарником, SQL-каталогом и файлом helicopter.db. Отдельно возможен узел CI (GitHub Actions) для сборки и тестов.
