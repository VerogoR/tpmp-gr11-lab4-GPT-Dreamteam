# Функциональные требования

## Актёры

- **Командир** — полное администрирование и аналитика.
- **Член экипажа** — просмотр собственных данных в рамках запросов, помеченных вариантом как доступные экипажу (`*`).

## Варианты использования (кратко)

1. **Войти в систему** — проверка логина/пароля в `AIR_USERS`, определение роли.
2. **Просмотр налёта и остатка ресурса** — по каждому вертолёту суммарная длительность рейсов после `date_last_fix` и сравнение с `flight_resource`.
3. **Отчёт по рейсам за период** — перечень рейсов с агрегатами по массе и пассажиропотоку (с учётом прав доступа).
4. **Сводки по спецрейсам и обычным рейсам** — количество рейсов, суммарная масса, суммарная стоимость (командир).
5. **Аналитика «максимумы»** — вертолёт с наибольшим числом рейсов (экипаж и деньги); экипаж с максимальными начислениями и перечень их рейсов.
6. **Рейсы экипажа / по вертолёту** — для летчика — свои рейсы; для командира — по выбранному вертолёту.
7. **Начисление за период** — расчёт по всем членам экипажа и запись в `AIR_PAYROLL_PERIOD`.
8. **Начисление летчику** — за интервал дат целиком; отдельно только спецрейсы или только обычные.
9. **CRUD** — вертолёты, экипаж, рейсы, пользователи (командир).
10. **Экспорт** — CSV по рейсам, JSON по вертолётам; сохранение тестового изображения в БД.

## Текстовый сценарий: «Войти в систему»

| Шаг | Действие |
|-----|----------|
| 1 | Пользователь запускает приложение и указывает при необходимости путь к БД. |
| 2 | Система открывает SQLite, при отсутствии таблиц выполняет скрипты создания схемы и расширений. |
| 3 | Пользователь вводит логин и пароль. |
| 4 | Система ищет запись в `AIR_USERS`; при неверных данных выводит ошибку и завершает сеанс. |
| 5 | Если `AIR_CREW_number` пусто — назначается роль **Командир**, иначе подгружается экипаж и роль **Экипаж**. |
| 6 | Отображается главное меню с набором пунктов в соответствии с ролью. |
