Функциональные требования

Актеры

  • Командир — полное администрирование и аналитика.
  • Член экипажа — просмотр собственных данных в сценариях, доступных для экипажа.

Варианты использования (кратко)

  1. Войти в систему — проверка логина/пароля в AIR_USERS, определение роли.
  2. Просмотр налета и остатка ресурса — суммарная длительность после date_last_fix и сравнение с flight_resource.
  3. Отчет по рейсам за период — список рейсов и агрегаты по массе/пассажиропотоку.
  4. Сводки по спецрейсам и обычным — количество, суммарная масса, суммарная стоимость.
  5. Аналитика максимумов — вертолет с максимумом рейсов и экипаж с максимумом начислений.
  6. Рейсы экипажа / по вертолету — по роли пользователя.
  7. Начисление за период — расчет по всем членам экипажа в AIR_PAYROLL_PERIOD.
  8. Начисление летчику — расчет за интервал дат (все/спец/обычные рейсы).
  9. CRUD — вертолеты, экипаж, рейсы, пользователи (командир).
  10. Экспорт — CSV по рейсам, JSON по вертолетам, тестовое изображение в БД.

Текстовый сценарий: «Войти в систему»

Шаг Действие
1 Пользователь запускает приложение и при необходимости указывает путь к БД.
2 Система открывает SQLite. Если таблиц нет — выполняет скрипты создания схемы и расширений.
3 Пользователь вводит логин и пароль.
4 Система ищет запись в AIR_USERS. При неверных данных выводит ошибку.
5 Если AIR_CREW_number пусто — роль «Командир», иначе роль «Экипаж».
6 Показывается главное меню согласно роли.
