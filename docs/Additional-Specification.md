# Дополнительная спецификация

## Надёжность и целостность данных

- Включены **внешние ключи** SQLite (`PRAGMA foreign_keys = ON`).
- Ограничение летного ресурса реализовано **триггером** до вставки в `AIR_FLIGHTS` (откат транзакции при нарушении).
- Инициализация схемы идемпотентна: базовые таблицы создаются из `HelicopterDelivery_create.sql`, расширения — из `extensions.sql` с `IF NOT EXISTS`.

## Безопасность

- Пароли в учебной БД хранятся **в открытом виде**; для production требуется хэширование и политика паролей.
- Разграничение доступа только на уровне приложения (роли командир / экипаж), без отдельного RBAC в СУБД.

## Удобство использования

- Консольное меню с нумерованными пунктами на русском языке.
- Подсказка по умолчанию для демо-входа при `HELI_SEED=1`.
- Флаг `--help` и переменные среды `HELI_SQL_DIR`, `HELI_SEED`.

## Производительность

- Объём данных учебный; индексы кроме первичных ключей не обязательны. При росте объёма рационально добавить индексы по `AIR_FLIGHTS(date)`, `AIR_FLIGHTS(AIR_HELICOPTERS_number)`.

## Сопровождаемость

- Разделение по модулям (`auth`, `queries`, `mutations`, `payroll`, `storage`, `db`).
- SQL вынесен в файлы, повторное применение при пустой БД.

## Общие функциональные ограничения

- Один файл SQLite на запуск (путь по умолчанию `build/helicopter.db`).
- Формат дат — строки `YYYY-MM-DD`, согласованные с seed-данными.
